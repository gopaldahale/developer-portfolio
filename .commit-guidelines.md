# Commit Message Guidelines

Generate professional, concise commit messages following this format:

## Format
```
<type>(<scope>): <subject>

<body>
```

## Types
- **feat**: New feature
- **fix**: Bug fix
- **refactor**: Code refactor
- **style**: Formatting, missing semicolons, etc.
- **perf**: Performance improvement
- **docs**: Documentation only
- **chore**: Build, deps, tooling

## Rules
- Subject: max 50 characters, lowercase, imperative mood
- Start with verb: add, fix, update, remove, refactor
- No period at end
- Body (optional): explain *why*, not *what*
- Body: wrapped at 72 characters

## Examples

### Feature
```
feat(ProjectCard): add image icon support
```

### Fix
```
fix(data): correct image path format for public folder
```

### Refactor
```
refactor(ProjectCard): extract icon rendering logic
```

### Fix with body
```
fix(ProjectCard): fix opacity on image icons

Remove opacity-60 class that made image icons too faint.
Use group-hover:scale-110 for consistent animation.
```

## Quick Commands
```bash
# Simple commit
git commit -m "feat(component): description"

# With body
git commit -m "feat(component): description" -m "Explanation of why this change."
```

## Templates by Feature
- **UI Component**: `feat(ComponentName): add/update feature`
- **Data Structure**: `feat(data): add/update project or field`
- **Bug Fix**: `fix(area): resolve issue description`
- **Performance**: `perf(area): improve performance metric`
- **Styling**: `style(component): adjust spacing or colors`
